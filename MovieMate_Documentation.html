Sections 01 – 07 4 Activities Architecture & Structure

01 Project Overview

MovieMate is a native Android application for personal movie tracking. Users register an account, log in, browse a movie catalog shown as a scrollable grid, mark movies as watched, rate them, view their complete watch history, and check personal statistics that include total watch time and a viewer rank.

Backend: PHP REST API running on a local XAMPP server at http://10.0.2.2/MovieMateAPI/. The address 10.0.2.2 is the Android Emulator's alias for the host machine's localhost. All traffic is currently HTTP (not HTTPS) — suitable for development only.

02 Architecture Pattern

MovieMate uses lightweight MVC (Model-View-Controller), the most common pattern in Android Java development.

LayerWhat it isFiles
ModelPlain Java objects that hold dataMovieItem.java, MovieHistoryItem.java
ViewXML layout files — visual structure only, zero logicAll res/layout/*.xml
ControllerActivities handle events and coordinate data flowAll *Activity.java

Supporting Design Patterns

PatternClassWhy it's used
SingletonVolleySingletonSingle shared HTTP request queue — avoids memory/thread waste
AdapterMovieAdapter, WatchHistoryAdapterBridge between data lists and RecyclerView display
ViewHolderInner classes inside each AdapterCache View references to avoid expensive repeated findViewById calls
Observer (implicit)RecyclerView notifyDataSetChanged()UI re-renders automatically when the backing data list changes

04 SplashActivity

File: SplashActivity.java  |  Layout: activity_splash.xml
Purpose: Branding screen shown for 5 seconds on app launch, then automatically redirects to Login. Contains the app logo and a progress bar.
onCreate (Bundle savedInstanceState) Lifecycle

Sets the content view to activity_splash.xml. Uses a Handler to post a delayed Runnable that fires after 5000 ms (5 seconds). When the delay fires it creates an Intent targeting LoginActivity, calls startActivity(), then finish() — preventing the user from pressing Back to return to the splash screen.

05 LoginActivity

File: LoginActivity.java  |  Layout: activity_login.xml
Purpose: Authenticates an existing user against the server and stores the session locally.

UI Components

IDTypeRole
usernameInputEditTextUser types their username
passwordInputEditTextUser types their password
loginButtonButtonSubmits the login form
signupButtonTextViewLink that navigates to SignUpActivity
onCreate (Bundle savedInstanceState)

Inflates the layout and binds all UI views. Sets click listeners on the login button and signup link.

Login button click — step by step:

  1. Reads username and password strings from the EditTexts.
  2. Validates neither field is empty — shows a Toast if validation fails, stops here.
  3. Builds a Volley StringRequest (HTTP POST) to login_user.php with params username and password.
  4. On server success: parses JSON response, extracts user_id, saves both username and user_id into SharedPreferences under key "MovieMatePrefs".
  5. Navigates to MainActivity and calls finish() so the user cannot go back to Login.
  6. On error: shows Toast with the server error message.
Session storage (SharedPreferences key "MovieMatePrefs"):
"username" → logged-in username  |  "user_id" → integer user ID from database

08 MainActivity

File: MainActivity.java  |  Layout: activity_main.xml
Purpose: The Movies tab — shows the full movie catalog as a 2-column scrollable grid. The central screen of the app.

UI Components

IDTypeRole
movieRecyclerViewRecyclerView2-column grid of movie cards
welcomeTextViewTextViewShows "Welcome, [username]"
profileIconImageViewTap to open the profile popup menu
bottomNavigationBottomNavigationViewHome / Movies / History tab bar
onCreate (Bundle savedInstanceState)

Reads username from SharedPreferences and sets the welcome message. Configures the RecyclerView with a GridLayoutManager (2 columns) and attaches a MovieAdapter. Pre-selects the Movies tab in the bottom nav. Sets tab-change listeners: Home tab → HomeActivity, History tab → WatchHistoryListActivity. Calls fetchMovies().

fetchMovies () Network

HTTP GET to get_movies.php. Receives a JSON array; each element has:

{ "movie_id": 1, "title": "Inception", "duration_minutes": 148,
  "genre": "Sci-Fi", "release_year": "2010", "image_url": "inception" }

Builds a List<MovieItem> and calls notifyDataSetChanged() on the adapter to refresh the grid.

showProfileMenu (View anchor)

Creates a PopupMenu anchored to the profile icon. Three options:

  • Username label — read-only display of who is logged in.
  • Change Password — starts ChangePasswordActivity, passes username as Intent extra.
  • Logout — clears all SharedPreferences, starts LoginActivity with FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK to wipe the entire back stack.

15 MovieAdapter

File: MovieAdapter.java  |  Item layout: movie_item.xml
Purpose: Binds the list of MovieItem objects to the 2-column grid in MainActivity. Each cell shows a full-height poster with gradient overlay, title, year, genre badge, and a "mark as watched" eye button.

Inner Class — MovieViewHolder

Caches view references for one grid cell to avoid repeated findViewById calls:

View fieldTypeDisplays
titleViewTextViewMovie title
posterViewImageViewMovie poster (loaded via Glide)
genreViewTextViewGenre badge
yearViewTextViewRelease year
markAsWatchedButtonImageButtonEye icon — tap to log as watched
onCreateViewHolder(ViewGroup parent, int viewType) → MovieViewHolderRecyclerView

Called when RecyclerView needs a brand-new cell. Inflates movie_item.xml and returns it wrapped in a MovieViewHolder.

onBindViewHolder(MovieViewHolder holder, int position)RecyclerView

Called to fill data into an existing cell. Gets the MovieItem at position. Sets title, genre, year. Calls getResId() to get the drawable resource ID, then loads the poster via Glide with a placeholder fallback. Sets a click listener on markAsWatchedButton → markMovieAsWatched(movie).

getResId(String name) → intUtility

Converts a movie name to an Android drawable resource ID. Steps:

  1. Lowercase the string.
  2. Replace spaces, hyphens, colons, apostrophes → underscores.
  3. Special case: "schindler's list" → "schindler_s_list".
  4. Calls context.getResources().getIdentifier(name, "drawable", packageName).
If a movie's title doesn't cleanly transform to a matching filename in res/drawable/, the poster silently falls back to the placeholder image.
markMovieAsWatched(MovieItem movie)Network

Triggered when the user taps the eye button. Gets today's date as YYYY-MM-DD. HTTP POST to add_watch_history.php via VolleySingleton with:

  • user_id — from SharedPreferences
  • movie_id — from MovieItem
  • watch_date — today's date
  • minutes_watched — from movie.getDurationMinutes()

Shows success or error Toast.

getItemCount() → int

Returns the total number of movies. RecyclerView calls this to know how many cells to create.

17 VolleySingleton

File: VolleySingleton.java  |  Pattern: Singleton
Purpose: One shared Volley RequestQueue for the whole app, plus automatic HTTP cookie/session management.

Fields

FieldTypeRole
instanceVolleySingleton (static)The one and only instance
requestQueueRequestQueueThe shared HTTP request queue
ctxContext (static)Application context — avoids Activity memory leaks
VolleySingleton(Context context)Private constructor

Private — no outside code can call new VolleySingleton(). Creates a CookieManager with CookiePolicy.ACCEPT_ALL and registers it as the system default CookieHandler. Every Volley request will automatically send and receive PHP session cookies without any extra code in each Activity.

getInstance(Context context) → VolleySingletonStatic / Thread-safe

The only entry point. Uses a synchronized block to prevent two threads from simultaneously creating two instances. Always passes context.getApplicationContext() to avoid leaking an Activity reference.

getRequestQueue() → RequestQueue

Lazy initialization — creates the queue on first call and returns the same one every subsequent call.

addToRequestQueue<T> (Request<T> req)Generic

Adds any Volley request to the shared queue. Used by activities as: VolleySingleton.getInstance(ctx).addToRequestQueue(myRequest).

Why a Singleton? Creating a new RequestQueue each time wastes threads and memory and breaks the disk cache. A singleton ensures one managed, reusable queue for the app's lifetime.

23 Known Issues & Limitations

1. HTTP only — no HTTPS. Passwords and session tokens travel in plain text. Must switch to HTTPS before any real deployment.
2. Hardcoded emulator host. All URLs use http://10.0.2.2/. Will not work on a physical device or remote server. Needs a config variable.
3. Legacy WatchHistoryActivity. Dead code with hardcoded userId = 1 and date. Should be deleted.
4. Brittle poster image loading. Poster filenames are guessed by transforming the movie title. Any mismatch silently shows the placeholder.
5. Minimal input validation. Password strength, username format, and rating range (1–10) are not enforced on the client side.
6. No offline handling. No connectivity checks — all failures surface only as Volley error Toasts with no retry.
7. SignUpActivity inconsistency. Creates its own RequestQueue instead of using VolleySingleton like every other screen.
8. No automated tests. Only auto-generated placeholder test files exist. All testing is currently manual.
